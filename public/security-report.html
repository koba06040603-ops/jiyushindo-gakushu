2. 認証・認可システム（96点）

2.1 パスワードハッシュ

  • PBKDF2-SHA-256（10万回反復）を採用。NIST SP 800-132推奨基準を満たす。
  • 128bitランダムソルト生成。レインボーテーブル攻撃を防止。
  • レガシーSHA-256/bcryptからの自動移行機構あり。
  • タイミング攻撃対策：定数時間比較 timingSafeEqual() を実装。
  • パスワード強度ポリシー：8文字以上、英字+数字必須。全登録系統に適用。

2.2 JWTトークン・セッション管理

  • HMAC-SHA256署名。Hono組み込みの sign() / verify() を使用。
  • JWT秘密鍵は環境変数 JWT_SECRET 必須（未設定時はエラー停止）。
  • 【FB1対応】リフレッシュトークン方式：アクセストークン1時間 + リフレッシュトークン7日間。D1にセッション保存。
  • 【FB2対応】セッション即時無効化：D1の user_sessions / auth_sessions テーブルでセッションを管理。不正アクセス検出時にセッションレコードを削除することで即時無効化可能。
  • 【FB9対応】JWT_SECRET定期ローテーション手順：wrangler secret putによる鍵更新手順を文書化。

2.3 Cookie設定

  • httpOnly: true — JavaScriptからアクセス不可。
  • secure: true — HTTPS通信のみ。
  • sameSite: 'Strict' — CSRF対策として有効。

2.4 ログイン保護

  • ログイン失敗5回でアカウントロック（15分間）。
  • 残り試行回数をレスポンスで返却。
  • 【FB3対応】第2系統（usersテーブル）はD1永続化済み。failed_login_attempts・locked_until カラムで管理。Worker再起動でもリセットされない。
  • 第1系統（auth.ts）はインメモリ管理。再起動時リセットリスクあり（低優先度で永続化検討）。
  • 第3系統（auth_usersテーブル/bcrypt）はロック機構未実装。将来統合時に対応予定。

2.5 ロールベースアクセス制御（RBAC）

  • 4つのロール：student, teacher, parent, admin
  • requireRole() / requireUserType() ミドルウェア実装済み。
  • 全APIに認証ミドルウェア適用。ホワイトリスト方式で10件のみ公開。
  • 【FB4対応】保護者アクセス制限：parent_student_relations テーブルで親子紐付け。保護者は自分の子どものデータのみアクセス可能。

4. フロントエンドセキュリティ（80点）

4.1 XSS（クロスサイトスクリプティング）対策

  • DOMPurify v3.1.6導入済み。CDN経由で自動読み込み。
  • window._safeHTML() グローバル関数を提供。全HTMLサニタイズに使用可能。
  • サーバーサイド sanitizeInput() によるHTMLタグ・イベントハンドラ除去。
  • 【FB8対応】innerHTML移行方針：DOMPurifyベースの _safeHTML() が全ページで利用可能。ユーザー入力がレンダリングされる箇所を優先的に移行中。
  • innerHTML の使用が index.tsx に207箇所、app.js に775箇所。段階的に _safeHTML() 適用を継続。

4.3 CSP（Content Security Policy）

  • 'unsafe-eval' 削除済み。eval() は禁止。
  • frame-src: YouTube/YouTube NoCookieのみ許可。
  • base-uri 'self': ベースURL改ざん防止。
  • form-action 'self': フォーム送信先制限。
  • frame-ancestors 'none': クリックジャッキング防止。
  • 'unsafe-inline' はTailwind CSS CDN版に必須のため維持。将来のビルド時CSP対応を検討。

4.4 機密データの露出防止

  • APIキーはサーバーサイドのみ（env.GEMINI_API_KEY）。フロントエンド露出なし。
  • JWTトークンはhttpOnly Cookieに保存。JSアクセス不可。
  • 答え漏洩防止: stripAnswerSections()、filterAnswerFromText() 実装済み。

5. データ保護・秘密情報管理（87点）

5.1 秘密情報管理

  • .dev.vars は .gitignore に含まれている。
  • 本番: wrangler pages secret put でCloudflare Secretsとして管理。
  • 管理対象: JWT_SECRET, GEMINI_API_KEY, CLOUDFLARE_API_TOKEN
  • JWT_SECRET未設定時はサーバー起動停止（フォールバック秘密鍵を完全削除）。
  • 【FB9対応】JWT_SECRETローテーション手順を文書化：wrangler secret put JWT_SECRET → Worker自動再起動 → 既存セッションは自然失効（最大1時間）。推奨頻度: 3ヶ月ごと。

5.2 データベースセキュリティ

  • Cloudflare D1（SQLite）。Cloudflareインフラで物理的に保護。
  • パスワード: pbkdf2:100000:salt:hash 形式。平文パスワードは保存されない。
  • 【FB10】個人情報（氏名・メール）は暗号化されずに保存。AES暗号化の実装を計画中。D1のプラットフォーム暗号化で物理層は保護済み。

5.3 通信セキュリティ

  • Cloudflare Pages でデフォルトHTTPS。TLS 1.2以上を強制。
  • HSTSヘッダー設定済み（max-age=1年、includeSubDomains、preload）。

5.4 バックアップ戦略

  • D1 Time Travel：Cloudflare D1の組み込み機能で過去30日間の任意時点への復元が可能。
  • 手動エクスポート：/api/admin/export/:type（CSV/JSON）で管理者がデータをダウンロード可能。
  • 【FB11】日次自動バックアップ（Cron Trigger + R2）は計画段階。D1 Time Travelにより緊急時のリストアは可能。
