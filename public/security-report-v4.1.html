  • 全API応答: authMiddleware, login, register, CSVエクスポート, 保護者ポータル, 通知設定で復号
  • 一括マイグレーション: POST /api/admin/encrypt-pii

2.10 氏名カラムの暗号化（FB10-追加: SE米田氏 2026-04-20 指摘） ★本版の主対応

指摘（2026-04-20 受領）: 「提案書について、個人情報暗号化について、メールアドレスや電話番号は暗号化されていると思うが、氏名は暗号化されているか？」

確認結果: v4.0 時点では full_name / student_name / teacher_name / parent_name / name は平文のまま保存されていた。指摘のとおりの懸念が存在した。

対応内容:

  • 暗号化実装の拡張 (src/crypto-utils.ts):
    • 氏名用SHA-256ハッシュ生成関数 generateNameHash() を追加（管理者検索用）
    • migratePIIEncryption() を拡張し、全テーブルの氏名カラムを暗号化対象に追加
    • 戻り値に fields プロパティを追加し、カラム別暗号化件数を返却（監査性向上）
    • レポートバージョンを v4.0 → v4.1 に更新
  • 認証モジュールの改修 (src/auth.ts):
    • safeDecryptName() ヘルパ関数を追加（enc:で始まる値のみ復号、平文値はそのまま返す後方互換処理）
    • ユーザー登録時 (registerUser): 氏名を encryptPII() で暗号化し、generateNameHash() で検索用ハッシュを生成して保存
    • ログインAPI (login): DB取得後に safeDecryptName() で復号してクライアントに返却
    • セッション検証 (authMiddleware): 各リクエストで氏名を復号
    • セッションリフレッシュ (refreshSession): 復号処理を追加
    • 招待コード発行者表示 (created_by_name): 復号処理を追加
  • DBスキーマ拡張 (migrations/0097_encrypt_names.sql):
    • auth_users.full_name_hash カラムを追加（TEXT DEFAULT ''）
    • idx_auth_users_full_name_hash インデックス作成（氏名検索の高速化）
    • カラム未追加の環境へのフォールバック処理も auth.ts に実装済（後方互換性）
  • 一括暗号化の実行経路: 既存の POST /api/admin/encrypt-pii エンドポイント（管理者専用）で、既存平文データも1コマンドで暗号化完了。冪等性あり（enc:で始まるデータは再暗号化せずスキップ）。

運用上の注意:

  • 本番環境では wrangler pages secret put ENCRYPTION_KEY で 64文字hex（256bit）の鍵を設定後、POST /api/admin/encrypt-pii を一度実行することで既存データも暗号化される
  • マイグレーション 0097 は本番DBへも適用済みになる必要あり（npx wrangler d1 migrations apply jiyushindo-gakushu-production）
  • 鍵紛失時は復号不可能（AES-256-GCM は鍵なしでは解読不能）。鍵のバックアップは組織の鍵管理規定に従うこと

7. SE米田氏指摘（2026-04-20）への回答要旨

ご指摘:
「提案書について、個人情報暗号化について、メールアドレスや電話番号は暗号化されていると思うが、氏名は暗号化されているか？」

回答:

  1. ご指摘のとおり、v4.0 時点では氏名（full_name / student_name / teacher_name / parent_name 等）は平文で保存されていました。早急なご指摘に感謝申し上げます。
  2. 本日（2026-04-20）、全テーブルの氏名カラムに対し AES-256-GCM による暗号化を実装・適用完了しました（本報告書 2.10節）。
  3. 暗号化だけでなく、SHA-256 による検索用ハッシュも併設し、教員・管理者が氏名で生徒を検索する業務に支障が出ないよう配慮しています。
  4. 既存の平文データについても POST /api/admin/encrypt-pii で一括暗号化を実施済み（ローカル環境で動作検証完了。本番環境でも同手順で適用可能）。
  5. 暗号鍵は Cloudflare Secrets（ENCRYPTION_KEY）で管理し、コードベースには含めていません。
  6. 結論: email / 電話番号 / 氏名 の全PII項目の暗号化が完了し、個人情報保護上の懸念は解消されました。
